# AEROSCOPE watch API (v1)

Contract between the Apple Watch / iPhone apps (`AeroscopeKit/Networking`) and the
watch backend (`backend/src/app.mjs`). Both sides are tested against it: Swift unit
tests stub it, `LiveContractTests` drives the real Swift client against the running
Node implementation, and `backend/test/app.test.mjs` exercises every route.

Base URL: the `WatchApiUrl` stack output, e.g.
`https://abc123.execute-api.ap-south-1.amazonaws.com/prod`, or `http://localhost:8787`
for `backend/dev-server.mjs`.

## Conventions

| Header | Required | Meaning |
| --- | --- | --- |
| `x-api-key` | API Gateway | Usage-plan key. Stored in the Keychain on iPhone and watch. |
| `x-aeroscope-user` | user routes | Installation id shared by the iPhone and watch. |
| `x-aeroscope-user-key` | user routes | 256-bit secret generated by the app and kept in the Keychain. The backend pins its SHA-256 to the user id on first use (conditional write) and compares in constant time afterwards: wrong key → 403, missing → 401. A user id alone is not a credential. |
| `x-aeroscope-operator-key` | operator routes | Secret from the `OperatorKey` stack parameter. Without it the operator routes return 403 (disabled). |
| `x-aeroscope-client` | no | `watchOS` or `iOS`. The backend pushes alerts only for requests that did not come straight from the watch (operator moves, iPhone relays). |
| `Idempotency-Key` | mutations | UUID of the queued action. A repeated key returns the stored response with `"replayed": true` and no side effects (kept 7 days). |

- Dates are ISO 8601 (`2026-10-11T08:00:00.123Z`); offsets such as `+05:30` are accepted.
- Errors: `{ "error": "message", "code"?: "outside-coverage" | "unauthenticated" | "forbidden" }` with 400 / 401 / 403 / 404 / 405 / 409 / 5xx.
- With a Cognito authorizer attached, the token's `sub` is the user and the user headers are ignored.
- Public (no user credentials, still behind the API key): `health`, `city`, `air-quality/current`, `routes/compare`, `GET scenario`.
- `category` fields are informational. Clients always derive the category from `aqi`
  with the Indian AQI bands (0–50 Good … 401–500 Severe).
- Every reading derived from the scenario model has `"simulated": true`;
  `provenance` is `demo` unless the baseline table is marked `verified`.

## Read-only

### `GET /v1/health`
```json
{ "status": "ok", "version": "1.0.0", "provenance": "demo",
  "scenario": { "preset": "traffic-haze", "timeIndex": 3 }, "push": false, "realtime": true }
```
`push` / `realtime` are true only when SNS platform applications / AppSync Events are configured.

### `GET /v1/city`
Zone baselines (same shape as the web app's `ZoneDataset`, plus `geo` anchors and road
`links`), the active scenario and `generatedAt`. The watch caches this for offline estimates.

### `GET /v1/air-quality/current?lat=&lon=` (or `?zoneId=`)
```json
{ "reading": { "zoneId": "z-cp", "zoneName": "Connaught Place", "region": "central", "aqi": 236,
               "pm25": 102, "pm10": 241, "dominant": "PM2.5", "temperature": 26, "windSpeed": 2.6,
               "scenarioTime": "2026-11-14T15:00:00+05:30", "provenance": "demo", "simulated": true },
  "match": { "zoneId": "z-cp", "zoneName": "Connaught Place", "distanceKm": 0.12, "world": { "x": 3.1, "z": -15.4 } },
  "scenario": { "preset": "traffic-haze", "timeIndex": 3 }, "generatedAt": "2026-10-11T08:00:00.000Z" }
```
More than 5 km from every zone anchor → `404 { "code": "outside-coverage" }`.
`match.world` is the avatar position on the 3D city's ground plane.

### `POST /v1/routes/compare`
Body `{ fromZoneId, toZoneId, mode: walk|cycle|motor, plannedZoneIds? }` → `RouteComparison`:
```json
{ "id": "cmp:z-ig>z-rf:1791720000", "fromZoneId": "z-ig", "toZoneId": "z-rf", "mode": "walk",
  "current":     { "id": "planned:z-ig>z-cp>z-ndls>z-cc>z-rf", "kind": "planned", "zoneIds": ["…"], "zoneNames": ["…"],
                   "distanceKm": 8.2, "durationMinutes": 103, "averageAqi": 244, "peakAqi": 262,
                   "peakZoneName": "New Delhi Railway Station", "exposureIndex": 1999 },
  "alternative": { "id": "cleaner:z-ig>z-yb>z-rf", "kind": "cleaner", "…": "…" },
  "exposureReductionPercent": 20, "extraMinutes": 4,
  "note": "Cleaner route via Yamuna Riverfront cuts exposure by 20%.",
  "generatedAt": "…", "scenarioLabel": "Urban Traffic Haze · 15:00" }
```
`exposureIndex` = Σ segment km × mean segment AQI. An alternative is offered only if it cuts
exposure by ≥ 10 %.

### `GET /v1/trips/{tripId}`
`{ tripId, phase, plannedZoneIds, lastEvaluation, lastEvaluationSource: device|operator, lastEvaluationAt, alerts[] }`.
The watch polls this during live trips to pick up operator moves and their alerts.

### `GET /v1/alerts?limit=20` → `{ "alerts": [PollutionAlert] }` (newest first)
### `GET /v1/preferences` → `AlertPreferences`
### `GET /v1/scenario` → `{ preset, timeIndex, label }`

## Mutations (send `Idempotency-Key`)

### `POST /v1/trips` → 201
```json
{ "tripId": "<uuid from the watch>", "startedAt": "…", "mode": "walk", "source": "live",
  "origin": { "geo": { "lat": 28.5931, "lon": 77.2197 }, "zoneId": "z-lg", "world": null, "accuracyMeters": 10, "simulated": false },
  "destinationZoneId": "z-rf", "plannedZoneIds": ["z-lg", "z-ig", "z-cp", "z-ndls", "z-cc", "z-rf"] }
```
Trip ids are generated on the watch so a trip can start offline. Re-posting an existing
trip id returns its state. Response: `OperationResult` (below) with the origin evaluation.

### `POST /v1/trips/{tripId}/events`
`{ "type": "location" | "pause" | "resume" | "end", "at": "…", "location"?: LocationPayload, "deviceAlert"?: PollutionAlert }`

`deviceAlert` carries an alert the watch raised from cached data while offline; the
backend stores it under the same id (origin `device`) before evaluating, so the alert
is not repeated. Invalid transitions → 409.

```json
{ "tripPhase": "active",
  "evaluation": { "reading": { "…": "…" }, "match": { "…": "…" }, "upcoming": { "…": "next planned zone" },
                  "alert": { "id": "…", "tripId": "…", "zoneId": "z-cp", "zoneName": "Connaught Place", "aqi": 236, "pm25": 102,
                             "kind": "upcoming-zone", "origin": "backend", "status": "active",
                             "createdAt": "…", "scenarioLabel": "Urban Traffic Haze · 15:00", "simulated": true },
                  "suppression": null, "scenario": { "preset": "traffic-haze", "timeIndex": 3 }, "dataAsOf": "…" },
  "alert": null }
```
`kind`: `entered-zone`, `escalation` (worse than the last alert, bypasses the cooldown) or
`upcoming-zone` (next zone on the planned route). `suppression` explains a non-alert:
`disabled`, `no-active-trip`, `stale-data`, `below-threshold`, `already-warned`, `cooling-down`.

### `POST /v1/alerts/{alertId}/actions`
`{ "action": "acknowledge" | "dismiss" | "request-route", "at": "…", "mode"?, "currentZoneId"?, "destinationZoneId"?, "plannedZoneIds"? }`
→ `{ "alert": PollutionAlert, "routeComparison": RouteComparison | null }`

### `POST /v1/trips/{tripId}/route`
`{ "routeId": "…", "choice": "alternative" | "current", "zoneIds": ["z-ig", "z-yb", "z-rf"], "alertId"?: "…", "at": "…" }`
→ `{ tripPhase, plannedZoneIds, alert }`. An accepted alternative replaces the rest of the planned route.

### `PUT /v1/preferences`
`AlertPreferences` (`alertsEnabled, threshold, cooldownMinutes, onlyDuringTrips, sensitiveGroup, lookAhead, travelMode, staleAfterMinutes, updatedAt`).
Last writer (by `updatedAt`) wins across watch, iPhone and backend.

### `PUT /v1/devices/{deviceId}`
`{ "token": "<APNs token hex>", "platform": "watchOS", "environment": "sandbox" | "production", "bundleId": "…" }`
→ `{ "registered": true, "push": <SNS endpoint created> }`

### Demo operator routes (`x-aeroscope-operator-key`; name the trip owner in `x-aeroscope-user`)
- `POST /v1/trips/{tripId}/simulate` `{ "zoneId": "z-an" }` or `{ "lat", "lon" }` — moves the trip's avatar from outside the watch (a presenter's laptop). Alerts it raises are pushed to the user's watches; the watch also sees them by polling `GET /v1/trips/{id}`.
- `PUT /v1/scenario` `{ "preset", "timeIndex" }` — pins the scenario. Otherwise the backend uses the scenario last saved from the 3D dashboard (`ScenarioSnapshots` table), else the IST clock with Urban Traffic Haze.

## `OperationResult`
Union response of every mutation: `{ tripPhase?, plannedZoneIds?, evaluation?, alert?, routeComparison?, replayed? }`.

## Real-time events for the web dashboard

Published to AWS AppSync Events (HTTP publish) on `/{namespace}/users/{userId}` and
`/{namespace}/trips/{tripId}`; the local dev server streams the same events at
`GET /v1/stream` (Server-Sent Events).

| `type` | Payload |
| --- | --- |
| `trip.started` | `tripId, mode, destinationZoneId, plannedZoneIds, at` |
| `trip.location` | `tripId, zoneId, zoneName, world {x, z}, aqi, category, simulated, source, at` — move the avatar to `world` |
| `trip.paused` / `trip.resumed` / `trip.ended` | `tripId, at` |
| `alert.raised` / `alert.updated` | `tripId, alert` |
| `route.compared` | `tripId, comparison` |
| `route.changed` | `tripId, choice, plannedZoneIds, at` |
| `scenario.changed` | `scenario, at` |

A dashboard subscriber needs only `trip.location.world` to place the character, and
`route.changed.plannedZoneIds` (zone ids map to `ZoneBaseline.position`) to draw the path.

## Push payload (APNs via SNS)
```json
{ "aps": { "alert": { "title": "Poor air ahead", "body": "Connaught Place · AQI 236" },
           "sound": "default", "category": "AQI_ALERT", "thread-id": "aqi" },
  "aeroscopeAlert": { "…": "PollutionAlert" } }
```
`AQI_ALERT` carries the actions **Cleaner route** (`AQI_ROUTE`, opens the app) and
**Got it** (`AQI_ACK`). Sent with `apns-push-type: alert` (required on watchOS).
